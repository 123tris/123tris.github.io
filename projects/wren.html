C# vs. Wren

自作C++エンジンTristeonにはスクリプトの仕組みがありませんでした。採用を決める前に、二つの候補を計測しました。Luaに近い小さな組み込み言語のWrenと、ゲーム開発で広く使われているもののC++への組み込みが難しいC#です。

C++ · C# · Wren · ベンチマーク

計測項目

エンジンにとって実行速度は要素の一つにすぎないため、次の三つを計測しました。

  • 実行性能：四則演算、リストへの追加、ユーザー定義型の生成をそれぞれ10万回。
  • コンパイル時間：変更が実行可能になるまでの時間。デザイナーの試行錯誤の速さを左右します。
  • C++呼び出しのコスト：言語の境界をまたぐ呼び出し一回あたりのコスト。エンジンのスクリプトの処理の多くはエンジンの呼び出しです。

WrenはCライブラリなので薄いC++ラッパーだけで済みます。C#の選択肢はP/Invoke、COM相互運用、埋め込み相互運用型、Monoによるホスティングでした。

// Arithmetic (C#)
for (int i = 0; i < 100000; i++)
{
    int x = 0, y = 10;
    int result = x * y / (i + 1);
}

// Collections (Wren)
var items = []
for (i in 1..100000) {
    items.add(i * i)
}

結果

計測方法：実行性能のベンチマークは上のループ（10万回）を、両言語で同じように書いたものです。大学での短い調査であり本格的なベンチマークではないため、結果は正確な値ではなく桁の目安として見てください。こうした数値はハードウェア、ランタイムのバージョン、JITのウォームアップによって変わります。

結論

C#は6〜15倍速く動作しました。一方Wrenはコンパイルが1000倍以上速く（53µs対88ms）、C++の呼び出しは1ms未満でした（C#は117ms）。

どちらが適しているかは、スクリプトの用途によります。エンジンのゲームプレイスクリプトの多くはエンジンの機能同士をつなぐもので、C++を頻繁に呼び出し、頻繁に書き換えられます。この用途にはWrenの低い呼び出しコストと短いコンパイル時間が向いています。重い計算はどちらの場合もC++で書きます。
