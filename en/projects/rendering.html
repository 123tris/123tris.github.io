3D rendering

OpenGL work in C++: a fragment shader that draws a checkerboard in a moving quad's own space and lights it around the mouse cursor, and a camera for a small engine whose look-at transform I built by hand from three vectors.

C++ · OpenGL · GLSL · 2016, 2019 · solo

The quad circles the window while the light follows the mouse. Recorded with the light radius raised from 20 to 150 pixels so the effect is visible at this size.

Checkerboard and spotlight

In 2019 I wrote an OpenGL 3.3 program that draws a quad of two triangles from a vertex and an index buffer with position, colour and UV attributes, and moves it around the window through an offset uniform set from the elapsed time. Its fragment shader draws the checkerboard in the quad's own UV space, so the pattern moves with it: the tile index on each axis is the floored UV times the tile count, and an even sum picks the first colour. The tile counts and both colours are uniforms set from C++.

The light is a falloff around the mouse: the colour is multiplied by one minus the fragment's distance to the cursor divided by 20, so it is brightest at the cursor and black from 20 pixels away. GLFW reports the cursor's y from the top of the window while gl_FragCoord counts from the bottom, so the host flips y before passing the position in.

#version 330 core
out vec4 fragColor;

in vec3 vertexColour;
in vec2 UV;

uniform uvec2 tiles;
uniform vec3 tileColourA;
uniform vec3 tileColourB;
uniform vec2 mousePos;

void main()
{
    vec3 colour;
    float sum = floor(UV.x * tiles.x) + floor(UV.y * tiles.y);
    bool isEven = mod(sum,2.0) == 0.0;
    if (isEven) {
        colour = tileColourA;
    } else {
        colour = tileColourB;
    }

    vec2 difference = mousePos - gl_FragCoord.xy;
    colour *= 1-length(difference)/20;

    fragColor = vec4(colour,1);
}

Look-at camera

In 2016 I wrote a camera behaviour for a small C++ engine. Instead of calling glm::lookAt, it builds its matrix itself: forward is the normalized vector from the target to the camera, right is the cross product of world up and forward, and up is forward × right. These three vectors and the camera's position are the columns of its transform.

void CameraBehaviour::update(float pStep)
{
    getInput();
    glm::vec3 forward = glm::normalize(_owner->getLocalPosition() - target->getLocalPosition());
    glm::vec3 right = glm::cross(glm::vec3(0, 1, 0), forward);
    glm::vec3 up = glm::cross(forward, right);

    _owner->setTransform(
        glm::mat4(glm::vec4(right, 0), glm::vec4(up, 0), glm::vec4(forward, 0),
                  glm::vec4(_owner->getLocalPosition(), 1))
    );

    _owner->getWorldPosition();
    if (sf::Keyboard::isKeyPressed(sf::Keyboard::Key::Q)) _owner->translate(glm::vec3(0, speed, 0));
    if (sf::Keyboard::isKeyPressed(sf::Keyboard::Key::E)) _owner->translate(glm::vec3(0, -speed, 0));
    _owner->translate(glm::vec3(-inputH * speed, 0, -inputV * speed));
}

Moving around the target

The behaviour applies this every update and then moves the camera in its own space: W/S toward and away from the target, A/D sideways, Q/E up and down. Moving sideways while turning back toward the target each frame makes it circle the target. In the clip it circles the brick teapot; the monkey's rotation is a separate behaviour.
