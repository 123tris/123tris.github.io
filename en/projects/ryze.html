Ryze

A 2D precision platformer about climbing by throwing yourself, made by Idomi Games, the studio I co-founded. As a programmer on the team I focus on how the character feels to control and on the mechanics the levels are built from.

Unity 6 · C# · 2022 — present · Steam playtest out now

Steam page itch.io

One verb, done well

Ryze has a single movement verb: charge a throw, release a pearl, and teleport to wherever it lands. The character controller runs on a small state machine (grounded, aiming, pearl in flight, respawning), and a lot of care goes into the moments between states. A press just before landing is buffered, so it still counts. Walking off an edge turns you into the pearl instead of dropping you. Probes under each foot notice when you are teetering on a ledge, so the animation can react before you fall.

The pearl bounces off walls and rolls down slopes, and on long throws the camera hands over to it, so the player never loses sight of where they will land.

A test level for every mechanic

Every mechanic I add gets its own station in one long technical test level. A change to the controller can be checked against all of them in a minute, and designers see each component working on its own before they use it in a real level. Each one is a self-contained component, tuned from the inspector.

Time bubbles are one of them. The character, the pearl and the pistons each run on their own timeline (built on the Chronos plugin), so a bubble changes the speed of everything inside it: movement, physics and animation slow down or speed up together.

Recorded in the test level. Other stations cover moving and slippery platforms, pistons, dialogue triggers, area banners and Japanese text.

A dialogue system that travels

I wrote this dialogue system for an earlier project and brought it into Ryze with its core unchanged. Three decisions made that possible:

  • It knows nothing about the UI. Each line goes out as a Ripple event. Every NPC listens and shows its speech bubble only when the line is theirs and the player is close, and the dialogue sounds listen to the same event. A new project only needs a new view.
  • The caller decides when a line moves on. Starting a dialogue is one awaitable call that takes the condition for advancing. Trigger zones, walk-up cutscenes and lines that react when the player keeps failing at a checkpoint are each a small component around that call.
  • Dialogues are data. Writers edit lines and speakers as assets in the inspector, and every line has a localized version that falls back to the English text.
