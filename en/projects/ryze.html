Ryze

A 2D precision platformer by Idomi Games, the studio I co-founded. The player climbs by throwing a pearl and teleporting to where it lands. I am one of its two programmers; my work covers the character controller, level mechanics and their test level, and the dialogue system.

Unity 6 · C# · 2022 — present · playtest on Steam

Steam page itch.io

Character controller

Movement consists of one action: charge a throw, release a pearl and teleport to where it lands. The controller is a small state machine (grounded, aiming, pearl in flight, respawning), and the transitions between states handle these cases:

  • A throw pressed shortly before landing is buffered and applied on landing.
  • Walking off a ledge turns the player into the pearl instead of starting a fall.
  • A probe under each foot detects when the character stands on the edge of a ledge, so the animation can react before a fall.

The pearl bounces off walls and rolls down slopes. On long throws the camera switches its target to the pearl, which keeps the landing point on screen.

Mechanics test level

Each mechanic I add gets its own station in a single technical test level. A controller change can be checked against every station in about a minute, and designers can try each mechanic in isolation before using it in a level. Each mechanic is a self-contained component configured in the inspector.

Time bubbles are one of these mechanics. The character, the pearl and the pistons each run on their own timeline (Chronos plugin), so a bubble scales time for every object inside it: movement, physics and animation slow down or speed up together.

Recorded in the test level. Other stations cover moving and slippery platforms, pistons, dialogue triggers, area banners and Japanese text.

Dialogue system

I wrote this dialogue system for an earlier project and reused it in Ryze without changes to its core. Three design decisions make it reusable:

  • No UI dependency. Each line is raised as a Ripple event. Every NPC listens and shows its speech bubble only when the line is its own and the player is in range; the dialogue sounds listen to the same event. Another project only needs its own view.
  • The caller controls advancing. Starting a dialogue is a single awaitable call that takes the condition for moving to the next line. Trigger zones, walk-up cutscenes and lines that play after repeated failures at a checkpoint are each a small component around that call.
  • Content is data. Writers edit lines and speakers as assets in the inspector. Each line has a localized version that falls back to the English text.
